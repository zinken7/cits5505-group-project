Feature 2 Real-time Messaging

Friends-only chat via WebSockets (Flask-SocketIO). Messages are persisted to the database. History is loadable via a REST endpoint. The friendship gate in friend_service.are_friends() must pass before any message is delivered.

read_atDateTimenullableNULL = unread. Set when recipient opens the conversation.
Add a composite index on (sender_id, recipient_id) and (recipient_id, sender_id) for fast conversation queries.

The private room name for a conversation between users A and B should be deterministic and order-independent:

room = f"chat_{ min(a, b) }_{ max(a, b) }"

WebSocket Events — app/sockets/chat.py

All events require an authenticated session. Use @login_required style check at the top of each handler.

Client → Server join_chat Payload: { "friend_id": int }. Server verifies friendship, then calls join_room(room_name). Emits chat_history back to the joining client only.
Client → Server send_message Payload: { "recipient_id": int, "body": str }. Server calls message_service.send_message(), then emits new_message to both users in the room.
Server → Client new_message Payload: message dict with id, sender_id, body, created_at, tags[]. Broadcast to the private room. Frontend appends to chat window.
Server → Client chat_history Payload: { "messages": list[dict] }. Sent once on join_chat so the client can render prior messages without a separate HTTP request.
Server → Client message_error Payload: { "error": str }. Sent to the emitting client only when validation fails (not friends, empty body, etc.).
Flask-SocketIO must be initialised in app/extensions.py and wired into create_app(). The socketio object — not app — must be passed to run.py.

REST Endpoints — app/api/v1/messages.py

Feature 3 Movie Tagging in Messages

Users can reference any media item inside a chat message with a #Title hashtag. When the tag matches a title in the database, it becomes an interactive element showing a hover/click preview card. No new DB table needed — tags are resolved at read time.

How It Works

  • 1User types a message containing #Inception or #Spirited Away (multi-word tags use spaces).
  • 2Server (inside message_service.send_message) calls tag_service.resolve_tags(body) which extracts #... patterns and looks each one up in Media.title (case-insensitive).
  • 3Resolved tags are returned alongside the message body in the new_message event payload and REST history response — the raw body is preserved unchanged in the DB.
  • 4Frontend receives { body: "...", tags: [{text, media_id, imdb_id, title, image_url}] } and replaces each #Tag span in the rendered message with a hoverable element.
  • 5Unmatched tags (no Media row found) remain as plain #text — no error, no special styling.
Storing the raw body and resolving tags at read time means tag data stays accurate even if a media item is renamed or added later — it will match on the next message load.

Service — app/services/tag_service.py

FunctionParametersReturnsDescription
resolve_tags body: str list[dict] Extract all #Word and #Multi Word patterns from the body. For each, query Media.title ILIKE tag_text. Return list of { text, media_id, imdb_id, title, image_url } for matched tags only. Unmatched tags are not in the list — frontend falls back to plain text for those.

Regex pattern for extraction (captures single-word and quoted multi-word tags):

#([A-Za-z0-9][A-Za-z0-9 ]{0,48}[A-Za-z0-9]|[A-Za-z0-9]+)
Multi-word tag matching is greedy — #The Dark Knight Rises could match The Dark Knight. Strategy: try the longest possible match first, then progressively shorter. Or restrict to single-word tags only and require CamelCase (#TheDarkKnight) for simplicity.

Wire into message_service.send_message:

tags = tag_service.resolve_tags(body)
# Include tags in the return dict for broadcast; body stored as-is in DB.

Frontend

  • 1In chat.js, add a renderMessage(msg) function. For each item in msg.tags, replace the matching #Text substring in the displayed body with <span class="media-tag" data-media-id="..." data-imdb-id="...">#Text</span>.
  • 2On desktop hover over .media-tag: show a floating popover with the poster image (image_url), title, and a link to /items/<imdb_id>.
  • 3On mobile tap: toggle the same content as an inline card below the message (no hover on touch screens).
  • 4The popover content is already in msg.tags — no extra API request needed to display it.
  • 5Style with data-ui="popover" if the UI Kit supports it, otherwise build a lightweight CSS tooltip. Add styles to app/static/css/chat.css (new file).
The poster URL in tags[].image_url is the same value from Media.to_dict(). If a local poster file exists at /static/posters/<imdb_id>.jpg it will be served from there; otherwise the CDN URL is used — this is already handled by _resolve_image() in the items API.
